## 2 · The index — 110 destinations, derived

    110 destinations   32 pages · 78 tabs
    56 synonyms        declared

Generated by `scripts/gen-nav-index.py` into `src/lib/nav-index.generated.ts` from
four authoritative sources: the sidebar (`AppLayout.businessSections`), the
`useTabParam` call sites, the cross-page groups in `route-tabs-config.ts`, and
`/dashboard`'s `_DASH_TABS` set.

### ⭐⭐ How the derivation avoids both failures — and both were mine

**(a) A shape-matching regex counted form fields as tabs.** `{ k, label }` matched
`fields: Array<{ k: keyof PeerRow; label: string }>` — **eleven peer-row inputs
reported as tabs, in two pushed reports.**

⭐ **FIX: membership is decided by the authoritative key list**, the same `*_KEYS`
const `useTabParam` validates the URL against. **Labels are joined onto keys that
are already known to be tabs; a label is never used to decide what a tab is.**
A form field is not in that list, so it cannot enter. **Verified: "EBIT",
"CapEx", "Total assets", "Prev-year rev.", "Curr. liab." — all absent.**

**(b) An early-return check missed a component exported past it.**
`BenchmarkingSection` sits below an unconditional `<Navigate/>` in
`benchmarking.tsx` yet renders inside `/risk-analysis`.

⭐ **FIX: ownership comes from where the param is DECLARED, never from file
position.** `useSearch({ from: "/risk-analysis" })` names the owner.
**Verified: all four bench tabs are attributed to `/risk-analysis?bench=…`, not to
`/benchmarking`.**

## 3 · The guard — and it earned its keep before the feature shipped

`scripts/check-nav-index.py`, **in the frontend repo, in CI** (now 12 steps),
because that is where routes and tabs change.

It regenerates and diffs, requires every indexed route to exist in `routeTree`,
requires **every declared synonym to resolve to an indexed destination**, prints
its denominators and refuses an implausible parse (§III.4). Its known-positive is
**a real route read out of `routeTree.gen.ts`**, never invented.

⭐⭐ **IT CAUGHT TWELVE BROKEN SYNONYMS ON ITS FIRST RUN** — and they were not bad
synonyms. They exposed a **real gap in the generator**: it was missing the
cross-page tab groups and `/dashboard`'s Set-declared tabs, so a third of the app
was unindexed. **The guard found a hole in the thing it guards, before either
shipped.**

⛔ **And then a non-nesting pattern skipped the one entry carrying `search: {}`** —
Benchmarking — leaving two synonyms unresolved. **The guard caught that too.**

**Controls, in memory:**

| control | result |
|---|---|
| a synonym pointing at `/nowhere` | ⭐ `✗ synonym 'ghost' -> /nowhere is not an indexed destination`, `rc=1` |
| delete one entry from the generated index | ⭐ `✗ nav-index.generated.ts is STALE`, `rc=1` |

⭐ The generated file is in `.prettierignore`: **its bytes are the contract**, and
reformatting it would make the drift check compare formatting instead of content.

## 4 · The synonyms — declared, and owned

`src/lib/nav-synonyms.ts`. **56 entries**, covering the vocabulary a CFO types:
*real options · WACC · EVA · RAEV · FCFF · distress · plan attainment · benchmark ·
peer set · breakeven · contribution margin · unit economics · margin bridge · DSO ·
DPO · working capital · P&L · Monte Carlo · efficient frontier · Shapley · RACI ·
Gantt · actuals · lineage.*

⭐⭐ **OWNER: whoever changes a destination's label owns its synonyms, in the same
commit** — stated in the file, and enforced by the guard, which fails when a
synonym stops resolving.

⛔ **NOTHING IS INFERRED.** This codebase has exactly one inference-by-name
mechanism — `KeyResult.kpi_key`, matched on normalised text — and it is **null on
all 82 rows.** Fuzzy-matching "DSO" onto a label containing "days" would be the
same bet at the same odds.

⭐ **A word with no single good answer is deliberately absent** rather than pointed
at the nearest page. DSO/DPO have no dedicated destination — they are ratio rows —
so they point at the ratio tab, which is the honest answer.

## 5 · Gated capabilities

**Shown and labelled.** A search for "multiverse" returns `/prescience-ai` **with a
Pro mark** — proven in the browser. ⛔ **Not silence** (the feature exists and a
buyer should know), ⛔ **not a 402 after the click.**

⭐⭐ **THE LABEL IS CLIENT-SIDE; NO FILTERING HAPPENS HERE AT ALL.** The palette
navigates; every destination enforces its own access. `use-capabilities.ts` states
the rule this respects: *"COURTESY ONLY: the API is the security wall."*

⛔ **No data search. No verbatim text.** A result naming a suppressed department
slice would defeat the k-floor, whose design assumes the count may be published
while the value is withheld.

## 6 · No dead ends

Every result is a **route plus the params that select the tab** — never a page to
hunt within, never a redirect alias. The index is generated from the same wiring
the router reads, so a result that resolves in the index resolves in the app.

⭐ **The empty state is not a dead end either.** It says what this searches and
what it does not, so a reader looking for a *figure* is sent to Ask AXIOM rather
than concluding the app has nothing.

## Proof

**Browser — cold context per search, in both modes. The assertion is the
destination, not the palette opening.**

    ✓ 'real options' → /valuation?tab=options          selects Real Options
    ✓ 'breakeven'    → /profitability?tab=contribution selects Contribution
    ✓ 'distress'     → /risk-analysis?sub=distress     selects Probability of Distress
    ✓ 'wacc'         → /valuation?sub=wacc             selects WACC Composition
    ✓ 'actuals'      → /twin?tab=sync                  selects Sync
    ✓ a PRO destination is SHOWN, and LABELLED Pro
    ✓ known-negative: an impossible query returns nothing
    ✓ the empty state says what this searches
    ✓ Escape closes the palette — it does not trap focus
    ANONYMOUS: 'real options' lands identically
